# TripleO Deployment Scripts

## Overview
Deployment scripts for TrilioVault (T4O) on TripleO-based OpenStack clouds (Train and Wallaby releases).
TripleO deploys OpenStack using OpenStack itself — services are configured via Puppet manifests and orchestrated via Heat templates.

## Directory Structure

```
tripleo/
├── tripleo-train/        # TripleO Train (OpenStack Train release)
│   ├── environments/     # Heat environment files (deployment parameters)
│   │   ├── trilio_env.yaml
│   │   ├── trilio_defaults.yaml (implied)
│   │   ├── trilio_endpoint_data.yaml
│   │   ├── endpoint_map.yaml
│   │   ├── trilio_nfs_map.yaml
│   │   └── trilio_env_tls_*.yaml
│   └── puppet/trilio/    # Puppet module for TrilioVault
│       ├── manifests/    # Puppet manifests (.pp)
│       │   ├── config.pp
│       │   ├── contego.pp        # DataMover service
│       │   ├── dmapi.pp          # DataMover API service
│       │   ├── horizon.pp        # Horizon plugin
│       │   ├── contego/          # DataMover sub-manifests (install, config, service)
│       │   └── db/mysql.pp       # Database setup
│       ├── templates/    # ERB config file templates
│       ├── files/        # Static files (Horizon plugin files, certs, scripts)
│       └── examples/     # Example site configs (NFS, S3, Swift backends)
│
└── tripleo-wallaby/      # TripleO Wallaby (OpenStack Wallaby release)
    ├── environments/     # Same layout as tripleo-train
    └── puppet/trilio/    # Same layout as tripleo-train
```

## Technology Stack
- **Puppet**: Primary configuration management (`.pp` manifests, `.erb` templates)
- **Heat**: OpenStack Orchestration for composable service deployment
- **TripleO**: OpenStack-on-OpenStack deployment pattern
- **ERB**: Ruby embedded templating for config file generation

## Key Conventions

### Train vs Wallaby
Each OpenStack release has its own subdirectory (`tripleo-train/`, `tripleo-wallaby/`) because:
- Package names and versions differ between releases
- Puppet class parameters may change between releases
- Heat service template schemas evolve

Always work in the subdirectory that matches the target OpenStack release.

### Puppet Manifests
- `contego.pp` is the DataMover service (also called contego internally)
- `contego/` sub-directory splits install / config / service into separate manifests
- `db/mysql.pp` handles database creation and user grants
- `files/` contains Horizon plugin Python files and S3 certificates copied to target nodes

### Heat Environment Files
- `trilio_env.yaml` — primary environment file, always included in deployment
- `trilio_env_tls_*.yaml` — additional files for TLS-enabled deployments
- `trilio_nfs_map.yaml` — NFS backup target per-project mount mapping
- `endpoint_map.yaml` — full Keystone endpoint map (generated by script)

### Deployment Flow
1. Stage container images on the undercloud
2. Include `environments/trilio_env.yaml` in the `openstack overcloud deploy` command
3. TripleO calls Heat → Heat calls Puppet classes → Puppet installs and configures T4O services
